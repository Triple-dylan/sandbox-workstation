# MVP plan — November 7

Confirmed: all application agents use OpenAI gpt-6-luna exclusively. No user model selector, per-agent override, alternate model fallback or client-controlled model field. Provider compatibility and account access must be verified before enabling calls. No deployment is production-ready with the existing name-picker login.

## Delivery order and acceptance

1. **Runtime and identity foundation.** Pin Luna centrally on the server for personal, project, specialist, routine and maintenance jobs. Remove OPENAI_MODEL override; reject model fields in public requests. Verify the actual provider endpoint and access rather than assuming a Codex model label is API-callable. Add Google sign-in with server-verified identity, secure sessions, logout and invitation-based project membership. Disable profile impersonation outside isolated tests. Never link old demo users by unverified display name. Acceptance: two Google accounts remain isolated, forged/expired callbacks fail, model override attempts cannot change execution.
2. **Canvas interaction repair.** Measure the destination Canvas before placing Graph resources: current Reader relies on a module-level canvasBounds even when Canvas is unmounted. Preserve one canonical resource identity, focus the placed item, and make movement discoverable without interfering with text selection. Constrain placement/movement against visible bounds, composer and fixed tools. Define smaller-window recovery explicitly; scrolling alone is not the requested always-within-borders behavior. Preserve last valid position and Escape cancellation. Acceptance: place from Graph before ever opening Canvas, drag every resource type, resize/hide navigation and resize the window; every item remains reachable and editable without overlap or losing data.
3. **Native documents and sheets.** Add explicit document and sheet resource types backed by server persistence and revisions. Document MVP: headings, lists, links, selection, undo and autosave. Sheet MVP: cells, rows/columns, basic formulas, clipboard and undo. Choose maintained editing foundations after compatibility/license research. Canvas, Graph and chat open the same resource; no detached copies or new reader rail. Acceptance: create/edit/reopen from all three contexts and verify permissions with another account. Full spreadsheet compatibility is not implied.
4. **Group conversation redesign.** Main-area transcript with compact author grouping, threads and attached project resources; participant identities provide private conversation access. Keep group visibility obvious without routing menus. Preserve scroll, drafts and selected resources when traversing contexts. Show a concrete group-work scenario before adding components. Acceptance: two humans and an agent discuss/edit one resource, follow a thread, ask privately and return without a missend or lost context. No mock transcripts in the user workspace.
5. **Group goals and deployable agents.** Persist goals with owner, assigned agent, status, deadline and linked resources/conversations. Agents have versioned instructions, skills, authorized resource scope, enabled tools and routines. Routines need persisted triggers, next-run state, pause/resume, cancellation, retry and idempotency, not only a saved text instruction. Work and conversation remain primary; configuration expands in context. Acceptance: deploy a scoped agent, run a real routine, review a consequential proposal, update a linked goal and recover safely after restart. No client model choice anywhere.
6. **MVP deployment preparation.** Prepare reproducible build/start configuration, HTTPS origin/callback configuration, health checks, persistent database/storage, migrations, backups/restore and secret injection. Choose hosting after checking current service support for the Node SQLite server, SSE and background routines. One persistent instance is the initial architecture unless a database/worker migration is deliberately undertaken. Google OAuth credentials, approved callback domain, hosting account and API credits are external prerequisites. Prepare the artifact and configuration before deployment approval; do not expose name-picker authentication publicly. Acceptance: invite-only staging with Google login, two-account real work, restart persistence, live Luna execution, scoped routine execution and a tested restore.

## Current limits

The OpenAI runtime is now pinned to gpt-6-luna; its constructor and environment no longer select a model. A minimal live Chat Completions request returned HTTP 200 with model gpt-6-luna on November 7; the earlier billing failure did not recur. Full agent workflows still need live validation. Direct Google sign-in has an initial implementation (official token verifier, separate subject identities, expiring/revocable sessions, production guards), but no configured client or live Google verification. User asked about easier options; Firebase Authentication is recommended and provider selection remains open. A production Dockerfile is prepared but not container-tested or deployed. Native sheets and durable routine scheduling remain absent. Graph-to-Canvas placement now waits for the destination measurement; resize recovery and richer Canvas behavior remain open. Current notes support drag, but placement/bounds and richer resource interactions require redesign. Built-in tool checkboxes are not external plugin integrations.

## Required gates

Follow product-corrections.md. Fixed minimizable tools never take a column. No standalone agent dashboard or default popup solution. Each phase records verified/failed/blocked/not-checked outcomes, automated behavioral regressions and actual-browser evidence. Passing a build is not product acceptance. Preserve existing user data; migrations and authentication mapping need explicit recovery paths.
